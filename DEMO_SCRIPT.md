# 3–5 minute demo walkthrough

**0:00–0:30 — Overview**
- Open the dashboard and point out 32 employees, 5 pods, 24 brands and the process rules.
- Explain the sample staffing mix: 20 of 24 brands have one dedicated owner; four brands have three-person teams.

**0:30–1:15 — Generate a month**
- Select November 2026 and click **Generate roster**.
- Explain that the engine reads the process operating calendar, each employee's weekly off and approved absence records before creating shifts.

**1:15–2:00 — Explore roster perspectives**
- Open Roster and show Company, Pod, Brand, Process and Employee views.
- Point to the status colours, coverage percentage, validation list and CSV export.

**2:00–2:50 — Manual change and validation**
- Open a roster shift and change its status to leave or unavailable.
- Save and show the immediate coverage recalculation and any dated brand/process gap.

**2:50–3:50 — Post-generation unavailability**
- Open Time off and add an approved leave/unavailable date for an employee who owns a single-resource brand.
- The API updates the existing shift immediately. Return to Roster and show the new gap across that brand's required processes.
- Add a backup resource under Assignments, then regenerate/review to show how a manager can resolve it.

**3:50–4:35 — Configure the operation**
- Add or edit an employee, brand or process; update a brand/process operating calendar and minimum staffing.
- Explain that the scheduler reads these records and does not hard-code individual client names.

**4:35–5:00 — Close**
- Show the README answers to all eight assessment questions.
- Emphasize that rosters remain drafts until an operations manager reviews the validation results.
